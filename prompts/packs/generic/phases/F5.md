# F5: What Next

Question: **if nothing changes, where does it land, and what can be done about it?**

F5 is arithmetic with stated conditions. It is not a forecast. The difference is not
rhetorical: a forecast claims what will happen, a scenario states what follows from
an assumption and prints the assumption next to the number.

No model is fitted here. No trend is extended past the data window. No probability is
attached to any branch.

## Entry condition

F5 runs after F3 has a decomposition with zero residual, and after F4 has either
finished or marked itself inapplicable. Both are controller prerequisites, not
suggestions: a scenario built on an unexplained difference is a guess with decimals.

Take the anchor from F2, not from a new measurement:

```
anchor = 332.0        # last complete period, or the current level
anchor_base = 362.4   # the period before, already cited in F2
```

If F2 cited it, reuse that `E-###`. A second id for the same measurement makes the
report contradict itself in two sections.

## What a scenario is

| | Scenario | Forecast |
|---|---|---|
| Input | a measured value plus a printed assumption | a fitted model |
| Output | a value under that assumption | a value with a date attached |
| Language | "jika …, maka …" | "akan menjadi …" |
| Reader may | test the assumption | trust the analyst |
| Allowed here | yes | no |

Three rules follow, and they decide most cases:

1. **Every scenario differs from the others by a printed parameter**, not by wording.
   If two branches have the same inputs, they are one branch.
2. **Every scenario names the observation that would confirm it is happening.** A
   branch nobody can check is decoration.
3. **Every number in the branch is computed in a cell.** An assumption is prose; the
   result of applying it is a measurement of the arithmetic, and it carries an
   `E-###` like any other.

## Step order

| # | Step | Produces |
|---|---|---|
| 1 | restate the anchor and its period, and confirm the last period is complete | `anchor=… period=… complete=yes` |
| 2 | print the spread the branches will use | `n=… p10=… p50=… p90=… min=… max=…` |
| 3 | choose the horizon and state it | `horizon=1 period` or `horizon=level` |
| 4 | compute the three branches from the spread | one value per branch, each in a cell |
| 5 | check whether the branch range contains the anchor | `range_low=… range_high=… crosses_anchor=…` |
| 6 | compute the action bounds from F3 components or F4 steps | rows or measure units affected per action |
| 7 | write the actions with owner, date, and metric | three lines, each with a baseline |

## Anchor and horizon

- With a time column, the anchor is the **last complete period**. If the final period
  is partial, use the period before it and say so, exactly as F2 and F4 do.
- Without a time column, the anchor is the **current level**: the median of the
  primary measure, with `n`. Say that the data has no time axis, so the scenario is
  about levels, not periods.
- Default horizon is **one period** at the grain F2 used, or **one level** when there
  is no time column.
- Beyond one period, compounding assumes the period changes are independent, and
  they usually are not. If you go to two or three periods, print the compounded
  values, state the independence assumption in the same sentence, and mark the
  confidence `medium` at best.
- Never extend past the length of the data window. Six months of history does not
  support a twelve-month scenario.

## The range comes from the past

The uncertainty in F5 is not invented and not modelled. It is the spread that already
happened.

**With a time column and at least six period changes:**

```
changes = period_over_period_change(primary_measure)   # excludes the partial period
p10, p50, p90 = quantile(changes, [0.10, 0.50, 0.90])
```

| Statistic | Used as | Why |
|---|---|---|
| `p50` | base branch: the change repeats at its typical size | median resists one bad period |
| `p10` | pessimistic branch: a bad-but-observed period | not the worst ever, which is often one anomaly |
| `p90` | optimistic branch: a good-but-observed period | same logic, upper side |
| `min`, `max` | reported, not used as branches | a single outlier is not a scenario |

**With a time column and fewer than six changes:** use `min` and `max` as the branch
parameters, label the range "rentang yang pernah terjadi", and state that it is a
description of the past, not a bound on the future.

**Without a time column:** use `p10`, `p50`, and `p90` of the primary measure itself.
The branch reads "jika nilainya berada di level p10 yang teramati", and the range is
labelled "rentang level yang teramati". This describes the spread of the data, not a
movement over time, and the report must say so.

The base branch is **no intervention**: the same typical change repeats, or the level
stays at its median. It is the answer to "kalau dibiarkan". If the reader wants the
effect of an action, that is the action bound in step 6, not a fourth branch.

## Three branches

Exactly three, in this order, each one cell:

| Branch | Parameter | Statement form |
|---|---|---|
| pesimis | `p10` | "jika perubahan tiap periode sebesar -8,4 persen berulang, nilainya menjadi …" |
| dasar | `p50` | "jika perubahan tipe -3,1 persen berulang, nilainya menjadi …" |
| optimis | `p90` | "jika perubahan sebesar +2,6 persen berulang, nilainya menjadi …" |

Print the value, the parameter, and the arithmetic in one line so the branch can be
recomputed by hand:

```
branch=pesimis change=-0.084 anchor=332.0 value=304.1 horizon=1
```

The statement in evidence repeats the condition. A value quoted without its "jika"
becomes a prediction the moment it reaches the report, and the renderer cannot tell
the difference.

## Two checks before the branches are useful

**Does the range span the anchor?** Print `range_low` and `range_high` around the
anchor. If the range contains the anchor value, this method does not determine the
direction of the next period. Say that in one sentence. It is not a reason to hide the
branches, and it is not a reason to drop the bad periods until the range narrows:
choosing the range is choosing the answer.

With no time column this check is vacuous: the p10 to p90 range contains the median by
construction. Replace it with a comparison against F3: if the difference F3 measured is
smaller than the width of the level range, the range cannot separate the groups. Say
that the scenario describes spread, not a shift.

**Is the effect bigger than the noise?** Compare the expected gain of an action
against the median absolute period-over-period change from F3, or the within-group
spread for a group contrast. If the gain is smaller, the next measurement cannot
distinguish the action's result from normal movement. Then either choose a bigger
lever, or measure over more than one period, and write down which you chose. An action
whose result is unmeasurable is indistinguishable from an action that did nothing.

## Action bounds

An action is admissible only when it points at something F3 decomposed or F4 measured:
a component with a contribution, or a step with a loss count. "Tingkatkan kualitas
data" is not an action, it is a hope with a verb.

Compute the bound, do not assert it:

```
affected_rows  = rows_at_risk * recovery_share
affected_value = affected_rows * mean_value     # only if the measure is additive
```

- `recovery_share` is an assumption. State the number you used. Prefer a conservative
  share over full recovery, and label a full-recovery figure as `batas atas`.
- Print both inputs and the product. The product is an `E-###`; the share is not.
- If the measure is not additive, the bound stays in rows and the measure version goes
  to `cannot_answer`.
- If F3 concluded "tidak dapat diidentifikasi", the action is a test of a hypothesis.
  Register it as `H-###` with the metric that would resolve it, and keep it out of the
  findings until a cell prints the result.

Three actions maximum, ordered by the size of the measured loss they target. Each line
carries all five fields, and a line missing one is deleted rather than repaired:

| Field | Rule |
|---|---|
| apa | the change, in one sentence, naming the step or component |
| siapa | a role (operator, pemilik data, tim teknis), never a person's name |
| kapan | a date within the next seven days for starting, and a date for reading the result |
| diukur dengan apa | the metric, its baseline `E-###`, and the threshold that counts as success |
| batas | the computed bound, with its assumption |

## Writing

The report section is one table and one paragraph.

| Asumsi | Nilai akhir | Yang harus terlihat agar ini terjadi |
|---|---|---|
| perubahan -8,4 persen berulang | {{E-0xx}} | nilai periode berikutnya di bawah … |
| perubahan -3,1 persen berulang | {{E-0xx}} | nilai periode berikutnya mendekati … |
| perubahan +2,6 persen berulang | {{E-0xx}} | nilai periode berikutnya melewati … |

The paragraph, five sentences at most: the range and how many observations it came
from; the base branch; what confirms each end; the limit that this is past variation
and not a model; the one number to watch next.

No sentence may use "akan", "diperkirakan", "kemungkinan besar", or a percentage of
confidence. The conditional is the whole point.

## No chart

F5 draws zero charts.

- The body budget is already spent: F2 up to three, F3 up to two, F4 one.
- A fan chart reads as a forecast. The reader takes the middle line as the answer and
  the edges as unlikely, which inverts what the table says.
- The table carries the same information with the assumptions visible in the same row
  as the number.

If a figure is drawn despite this, it is three bars from one anchor, never a line with
a shaded band.

## Evidence discipline

| Claim | Entries |
|---|---|
| each branch value | one `E-###`, statement begins with "jika" and repeats the parameter |
| the spread behind the branches | one `E-###` carrying `n`, `p10`, `p50`, `p90` |
| each action bound | one `E-###`, with inputs and share printed |
| the baseline an action is judged against | the existing F2, F3, or F4 id, never a new one |
| the assumption itself | none. An assumption is a sentence, not a measurement |

A branch value with no condition attached is not evidence either, because it cannot be
checked: the reader cannot tell what would make it wrong.

## Prohibited in F5

- A single forecast number, or a fourth branch that is "most likely".
- Probabilities, confidence percentages, or the words "diperkirakan", "kemungkinan
  besar", "diproyeksikan".
- Branches that differ only in wording.
- Extending past the data window, or compounding without stating independence.
- Any model: regression, ARIMA, Prophet, exponential smoothing, ML.
- An action without owner, date, metric, or baseline.
- A bound computed with full recovery and presented as the expected outcome.
- An action aimed at a cause F3 refused to establish, unless registered as `H-###`.
- More than three actions.
- Any chart.
- Quoting a branch value without its "jika".

## Exit check

All of these must be true before `advance_phase`:

- anchor restated with its period or level, and completeness of the final period
  stated
- spread printed with `n`, and branches chosen from it by name
- horizon stated, with the compounding caveat if it exceeds one period
- three branches computed in cells, each printing its parameter and its value
- range and noise comparison both printed and interpreted
- action bounds computed, sorted by targeted loss, each with all five fields
- zero charts
- `evidence/F5.json` written, with no `E-###` for an assumption
- `cannot_answer` updated for any bound that could not be expressed in the measure's
  own unit
- at least one scenario exists, which is the controller prerequisite for F6
